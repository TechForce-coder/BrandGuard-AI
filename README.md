# BrandGuard AI — Frontend starter

React + Vite + Tailwind + React Router starter matching the supplied BrandGuard prototype.

## Run locally
1. Install Node.js (LTS).
2. From the repository root, move into the frontend directory and install its dependencies:
   ```sh
   cd client
   npm install
   ```
3. Create your local environment file by copying `client/.env.example` to `client/.env.local`. From inside `client`, run `Copy-Item .env.example .env.local` in PowerShell or `cp .env.example .env.local` on macOS/Linux.
4. Start the frontend from `client` with `npm run dev`, then open the URL printed by Vite.

`client/.env.local` is for your machine only and is ignored by Git. Do not commit it or put secrets or credentials in `.env.example`.

## API mode
- API mode is the default. Set `VITE_API_URL` to your backend API base URL.
- `VITE_USE_MOCKS=true` explicitly enables local development fixtures and browser storage. Mock authentication does not verify credentials and is not suitable for production.
- Keep local fixture mode out of production deployment configuration. Local fixtures and their role switcher are honored only by Vite development builds.
- The copied example enables `VITE_LOGIN_BYPASS=true` for local role-interface preview and keeps `VITE_USE_MOCKS=false`. The bypass does not create an account or token; it shows the development-only role switcher (Creator, Reviewer, Manager, and Admin) and permits access to existing role UI routes while clearly marking the session unauthenticated. API operations still require valid authentication. Set `VITE_LOGIN_BYPASS=false` or remove the setting to restore normal login.
- Set `VITE_USE_MOCKS=true` separately only when you want local fixtures. The local scan uses hard-coded text matching, and draft save/submit/review statuses are simulated in browser storage. Finding decisions are not persisted, and audit entries are fixture records rather than events generated by those actions. None of this represents a server-persisted approval workflow.
- Login bypass and mock data are enabled only in Vite development mode; production builds ignore both flags.

## Implemented starter screens
- Role-aware dashboard and navigation (Creator, Reviewer, Manager, Admin)
- Draft list/new draft/editor, scan and finding decisions
- Review queue, comments, approve/request changes
- Guideline library, facts register, and audit history views
- Responsive layout, empty states, loading and error feedback

## API integration status
Frontend API calls are centralized in `client/src/api/api.js`. The current server exposes only its root welcome endpoint; authentication, drafts, scanning, findings, rulebook, facts, and audit endpoints are not implemented in this repository's backend yet. Those screens require a compatible API service to return live data and perform workflow actions. In API mode, request failures are surfaced rather than silently replaced with local fixture data.
